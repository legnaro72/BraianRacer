# BRAIN RACER

## Full Development Specification for Codex

I want you to build a polished, highly engaging web game called **Brain Racer**.

This should NOT look like a simple Streamlit demo.

It should feel like a small arcade game with a real visual identity, smooth gameplay, persistent player profiles, leaderboards and a multiplayer mode.

The application must be built around **Python + Streamlit**, but the arcade driving portion should execute client-side in the browser for smooth animation and controls.

The final project must launch with:

```bash
streamlit run app.py
```

Do not stop at scaffolding, pseudocode, mockups or TODOs.

Produce a complete working application.

---

# 1. PRODUCT VISION

Brain Racer combines two different skills:

**REFLEXES + KNOWLEDGE**

The player must first survive an arcade driving challenge.

If they reach the finish line, they face a short general-knowledge quiz.

The fundamental game loop is:

DRIVE
→ SURVIVE
→ REACH THE FINISH LINE
→ ANSWER 3 QUESTIONS
→ EARN OR LOSE POINTS
→ ADVANCE TO A HARDER LEVEL
→ REPEAT

The visual experience should be energetic and arcade-like.

The intellectual part should feel competitive rather than educational or school-like.

The player should have the feeling:

> “I have to be fast with my hands and fast with my brain.”

# 30. MULTIPLAYER GAME PHILOSOPHY

Do NOT attempt to transmit every car coordinate between clients at 60 FPS.

That is unnecessary and inappropriate for this architecture.

Each player's actual driving simulation runs locally in their browser.

The server synchronizes only game state.

Examples:

* progress;
* level;
* score;
* lives;
* finish status;
* elimination status;
* quiz phase;
* match phase.

This should create the perception of synchronous multiplayer without turning Streamlit into a realtime game server.

---

# 31. SAME COURSE FOR ALL PLAYERS

A multiplayer round must be fair.

The server must generate and store a:

**game_seed**

All participants receive the same seed.

Obstacle generation should be deterministic from:

* game seed;
* level.

Therefore players face equivalent courses regardless of device.

Use normalized coordinates so viewport size does not affect difficulty.


# 57. DETERMINISTIC RANDOMNESS

For multiplayer, use seeded randomness.

Given:

```text
room_seed + level
```

the generated road/obstacle sequence should be equivalent for every player.

Do not rely on JavaScript `Math.random()` without seeded PRNG for multiplayer course generation.

Create a deterministic PRNG.
